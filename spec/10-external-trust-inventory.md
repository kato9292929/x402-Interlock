# 10 外側からの信頼：掲載ブランド名と受取先（payTo）の対応

2026-10-08。オーナーの指示書「外部からの信頼：掲載ブランド名と受取先の対応をカタログ全件で取る」に従う。
前回の指示書（観測データを分析側へ寄せる）を置き換える。09-2 は NOT MEASURED、09-3 は標本抽出が成り立たなかった。

この層は判定を出さない。観測した事実、観測日時、観測方法だけを出す。

## 1. 観測の棚卸し

| 観測対象 | 作り直せるか | 当社が全件で取れるか | 他者が持っているか | 根拠 |
|---|---|---|---|---|
| カタログの記載（名称・説明・価格） | 作り直せる | 取れている（131,675 件） | x402scan が持つ | endpoint@83e33d7 の `data/endpoints_full.json.gz`。記録の 131,587 件は source が x402scan |
| 応答ホスト（DNS・証明書・IP） | 痕跡が残る | 取れる（ネットワークが許せば） | 取れる | 公開の DNS と TLS。誰でも同じものを引ける |
| チェーン上の送金 | 作り直せない | **取れない** | TRM・Artemis が持つ | 下の制約 1〜3。09-2 が NOT MEASURED になった理由 |
| 払って何が返ったか | 作り直せない | 有料（2節と6節） | 誰も持たない | 09-3 の見積もり：100 ホストに 1 回ずつ払うと 4.23 USDC（1 USDC 上限）／12.73 USDC（上限なし） |
| 掲載ブランド名 ↔ 受取先の対応 | 片側（掲載）は作り直せる | 取れる（無料、未実行） | 誰も持たない | 402 応答の `accepts[].payTo` は支払いなしで読める（`research/probe-402.mjs`、模擬サーバーでのみ確認済み）。カタログは payTo を保存していない |

確定した制約（推測ではなく、PR #8 の報告で確認した事実）:

1. カタログに payTo の項目が無い。`scripts/x402-discovery.ts` は 402 応答の `accepts[].payTo` を読むが、保存しない。
2. この環境のネットワーク設定で、売り手ホストと Base / Solana の RPC への接続が止められている（2026-10-08 時点）。
3. TRM の分類結果は、アドレス単位では公開されていない。

**3行目（チェーン上の送金）は捨てる。** 制約 1 と 3 により、送金の相手を分類する材料を当社は持てない。制約 2 が解けても
制約 3 は残る。TRM と同じ土俵には立たない。5行目（無料）を先にやり、4行目（有料）は6節の条件が揃うまで着手しない。

## 2. 捏造の費用（結論：「支払った観測記録は捏造が高くつく」は成り立たない）

使う数字（09-3、endpoint@83e33d7、14日以内・USDC・per-call の 31,490 件）: 中央値 0.01 USDC、上位10% 0.05 以上、上位1% 1 以上。

| 積むもの | 100件の費用 | 状態 |
|---|---|---|
| (1) 第三者として「支払って応答を得た」記録 | 100 × 0.01 = **1.00 USDC**（中央値ベース） | 計算のみ |
| (1') 売り手が自分の出品に自分で払う場合 | 支払った USDC は自分の payTo に戻る。正味は手数料とガスだけ。x402 の exact 方式ではガスをファシリテーターが払う（PayAI は無料） | 正味が 0 に近いことは仕組みから言える。ファシリテーターの手数料は**要確認** |
| (2) ERC-8004 の評価を自己取引で 100 件 | 100 × 1 回分のガス | **要確認**。Base で 1 回 0.002〜0.04 USD 程度を仮定すると 0.2〜4 USD。ガス量・ガス価格・ETH 価格はいずれもこの環境で確認していない |

比（(1) ÷ (2)）: 仮定の範囲で 0.25〜5 倍。1桁に収まる。(1') を使えば、支払った記録の方がむしろ安い。

**結論:** 「支払った観測記録は捏造が高くつく」は主張として成り立たない。この行を根拠に使う案はここで打ち切る。
(2) の数字は仮定であり要確認だが、(1') が成り立つ限り、(2) をどう確認しても結論は変わらない。

同じ事実のもう一つの面: 記録を積む費用が安いことは、**当社が観測する費用も安い**ことを意味する。402 応答を読むだけなら
支払いは 0 で、払って中身を確かめる場合も 100 ホストで 4.23 USDC（1 USDC 上限）。不利な数字（捏造が安い）と
有利な数字（観測が安い）は、価格が安いという同じ1つの事実から出ている。

## 3-1. X・Y・Z（数字を見る前に固定）

対象と母集団: endpoint@83e33d7 の `data/endpoints_full.json.gz`。spec/09（adf7b29）と同じ条件（`price` があり、
USDC・per-call・amount > 0、`last_seen` が generated_at から 14 日以内、`networks` が空でない）を満たす
31,490 件、3,324 ホスト。**カバー率の分母は 3,324 で固定**する。読めなかったホストも分母から外さない。

### X：払うべき相手を特定できた

ホスト h について、プローブしたエンドポイントのうち少なくとも1つが HTTP 402 を返し、その `accepts` に
**payTo・金額・ネットワークの3つがすべて空でない**項目が1つ以上ある。v2 は `PAYMENT-REQUIRED` ヘッダー
（base64 の JSON）、v1 は本文の JSON から読む。金額は v2 の `amount`、v1 の `maxAmountRequired`。

カバー率 = X を満たすホスト ÷ 3,324。3-4 の線は 50%（指示書のまま）。

### Y：宣言したブランドと受取先が一致する

spec/09（adf7b29）の規則を流用する。**流用するもの:** endpoint@83e33d7 の `scripts/brands.mjs` をそのまま使う
（`BRANDS`・`HOSTING`・`GATEWAYS`、`firstPartyBrand`・`borrowedBrand`・`gatewayOf`。一覧に会社を足さない、規則を直さない）。
自社出品 F(B) と名前を掲げた出品 R(B) の定義も adf7b29 のまま（表示名は単語として一致、大文字小文字を区別しない）。

**変えるもの:**
- 単位を記録からホストにする。ホスト h は、その対象記録のどれかが F(B) なら B の自社ホスト、R(B) なら B の名前を掲げたホスト。
- 「組」（同じ機能・自社が安い）は使わない。比べるのは価格ではなく受取先。
- P(B) = B の自社ホストすべてで観測した (ネットワーク, payTo) の集合。

**照合（B の名前を掲げたホスト h ごと）:**
- **一致**: h で観測した (ネットワーク, payTo) のどれかが P(B) に含まれる。
- **不一致**: P(B) が空でなく、h の (ネットワーク, payTo) が P(B) と1つも重ならない。
- **照合不能**: P(B) が空（B に自社の x402 出品が無い、または自社ホストの payTo が読めなかった）、または h 自身の payTo が読めなかった。

複数のブランド名を掲げたホストは (ホスト, ブランド) の組ごとに照合する。ホストとしての集計は、不一致が1つでもあれば不一致、
不一致が無く一致が1つでもあれば一致、それ以外は照合不能。

**正規化:** ネットワークは `base` と `eip155:8453` を base、`solana` と `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` を solana にまとめる。
それ以外は値をそのまま使う。EVM のアドレスは小文字にし、Solana のアドレスはそのまま比べる。

**ゲートウェイと、他社名を含むだけのホスト:** どちらも adf7b29 と同じく R(B) に入る（ゲートウェイは名称か説明に B の表示名が出るとき、
他社名を含むだけのホストは `borrowedBrand` が B のとき）。ゲートウェイについては別に、同じ payTo が2つ以上のホストで観測された件数を
事実として数える。

**読み方:** 一致は「B 自身が運営している」ことを意味しない。不一致は「再販」を意味しない。どちらも、402 応答が指定した受取先が
B の自社ホストのものと同じだったか、という観測にとどまる。

### Z：全件に当てるときの手順・除外・打ち切り

- **エンドポイントの選び方**: ホストごとに、対象記録を URL 順に並べ、seed 20261008 の乱数（mulberry32）で1件選ぶ。
  ホストの順序も同じ乱数で並べる。その**最初の 200 ホスト**では、最大3件を追加で引き（ホストあたり最大4件）、
  同じホストの中で payTo が一致するかを確かめる。
- **要求**: GET。402 でなければ、同じ URL に POST（本文 `{}`）を1回。支払いのヘッダーは一度も送らない。リダイレクトは追わない。
- **待ち方**: 1要求のタイムアウト 15 秒。同じホストへの要求は 2 秒以上空ける。同時に扱うホストは 8 まで。
- **再試行**: 429 と 503 は `Retry-After`（無ければ 30 秒、最大 60 秒）待って1回だけ再試行。接続エラーとタイムアウトは
  10 秒後に1回だけ再試行。2回目も失敗したら記録して次へ。429 を2回受けたホストでは、残りのエンドポイントを引かない。
- **読めなかった理由の区分**: 接続不可（DNS・接続拒否・TLS・切断）、タイムアウト、402 以外（状態コードも残す）、
  形式不明（402 だが accepts を読めない、または X の3項目が揃わない）、プロキシ拒否（この環境のプロキシが接続を許可しなかった。
  相手側ではなく当社側の理由として別に数える）。
- **打ち切り**: (a) 最初の 50 ホストのうち 90% 以上がプロキシ拒否か接続不可なら、この環境からは届かないとみなして止める。
  数字は出さず、何ができなかったかだけを報告する。(b) 全体で 6 時間を超えたら止め、そこまでの件数を「途中」と明記して報告する。
- **保存**: `data/payto-observations.jsonl` に追記する。1行に observed_at、エンドポイント ID、URL、ホスト、方法、状態コード、
  402 の形式（v1 / v2）、accepts の各項目（network・asset・amount・payTo・scheme）、読めなかった場合は理由の区分。
